## 2. 愿景、定位与原则

### 2.1 一句话定位

> **一个普通人在 AI 浪潮中的公开编年史——写在一扇真实的窗边。**

它不是作品集，不是技术博客，也不是又一个“数字花园”模板。它是你的**长期公开记录**：
用**写作**训练表达与世界观（输出），用**规划与账本**记录一个普通人如何过日子、做选择（生活与经济），用**窗**给来访的人一种情绪（氛围）。
“QQ 空间式的小窝”在这里的含义是：**个人性、可停留、愿意常来**——而不是社交功能。

### 2.2 谁会读这个站

| 读者 | 他们想要什么 | 对设计的影响 |
|---|---|---|
| 同样处在 AI 浪潮里的普通人 | 共鸣、真实的选择与代价 | 叙事连贯：时间线、系列、复盘可追溯 |
| 关心“怎么用 AI / 怎么想 AI”的人 | 有论证的思考，而不是观点口号 | 论证结构、立场标注、修订可见 |
| 朋友与同行 | 近况、可信度 | “此刻”页、真实数据（规划模块） |
| **未来的你** | 看清自己怎么变的 | 修订史、观点演化、编年史（**最重要的读者**） |

### 2.3 设计原则（10 条，每条都可检验）

| # | 原则 | 怎么检验 |
|---|---|---|
| P1 | **窗外即世界**：首页只做一件事——让人停下来看。其余一切让路。 | 首页除导航、1–2 个入口、一行“此刻”外，无任何文字块 |
| P2 | **桌上即思考**：二级页以“读懂”为唯一目标，零装饰性动效。 | 阅读页不出现与内容无关的动画、渐变、光晕 |
| P3 | **自成体系，拒绝模板味**：字号、间距、配色三者构成一个可被复述的系统。 | 能用 5 句话说清这个站的排版/间距/配色规则（见 4.7 清单） |
| P4 | **真实优先**：真实天气、真实日期、真实数据；前期不填充任何假内容（R11）。 | 仓库里没有 lorem ipsum、没有占位签名/口号 |
| P5 | **Agent 对等**：人能做的，agent 都能做；agent 做的，人能审阅。 | 每个后台操作都有对应的 CLI/REST/MCP 工具（附录 B） |
| P6 | **内容与工具解耦**：内容契约稳定，写作前端与展示层都可更换。 | 换掉 Obsidian/Notion 不需要改站点代码 |
| P7 | **渐进增强**：无 JS、弱设备、减少动态效果时，站点依然完整可用。 | 关掉 JS 仍能读文章；`prefers-reduced-motion` 下首页是一张静态好图 |
| P8 | **默认私密，显式公开**：数据按字段设可见性，公开是一个动作而不是默认。 | 规划域每个字段都有可见性策略（第 8 章） |
| P9 | **小而可持续**：单人 + agent 可长期维护。复杂度是预算，不是荣誉。 | 任何新增依赖都要写明“退出路径”和“维护成本” |
| P10 | **可退出**：任何第三方依赖都能在一天内迁走（Markdown / JSON / Git 是底线）。 | 内容与数据都能以开放格式整体导出 |

### 2.4 非目标（这个项目**永远不做**什么）

- 不做通用 CMS、多作者平台、会员系统（除非未来明确转型）。
- **不在站内做编辑器**。写作发生在 Obsidian/Notion；站内只有“审阅与批准”（旧站“后台繁琐”的根因就是后台想做太多）。
- 不做社交网络功能（关注、私信、信息流）。“小窝感”靠氛围与个人性，不靠社交。
- **前期不填内容**：个人资料、自我介绍、口号、头像一律留空，等你提供（R11）。
- 不用动效炫技压过内容；任何装饰性视觉只允许出现在“窗”里。
- 不把财务**原始数据**放进站点仓库；仓库里只有“已决定公开”的快照。
- 不追求“功能齐全的后台”；宁可没有，也不要半成品。

### 2.5 成功标准（6 个月，🟡 数值待你确认）

| 维度 | 目标 |
|---|---|
| 稳定输出 | 累计 ≥ 20 篇长文；连续 ≥ 8 周不断更（目标：一周一篇） |
| 发布摩擦 | 一篇文章从“你交出原稿”到“全球可访问”，**你的介入 ≤ 2 次**（交稿、批准） |
| 体验 | 首页 LCP ≤ 2.0s（中端手机 4G）；阅读页 LCP ≤ 1.5s；阅读页 Lighthouse 性能 ≥ 95 |
| 国际化 | 英文版上线，译文 ≥ 10 篇；非大陆访问占比逐步 ≥ 30% |
| 主观 | “我愿意打开它写东西”——发布一篇所需的操作时间（不含写作）≤ 15 分钟 |
| 成本 | 月固定成本控制在你给定的上限内（见第 10 章，待托管调研校准） |

## 3. 内容体系

### 3.1 内容类型：一条“写作阶梯”

你的原文里有随笔、思考、学习笔记、生活、经济规划，并且说“缺少输出的锻炼、没有沉淀过知识库”。
我的建议是：**不按话题分栏目，而按“写作意图”分类型**，让它们连成一条从“抓住念头”到“完成论证”的阶梯：

```
短想法 thought ──► 笔记 note ──► 问答 qa ──► 随笔 essay
 (别丢掉念头)     (消化输入)    (回答一个问题)  (完整论证)
```

| 类型 | 写作意图 | 篇幅 | 节奏 | 特点 |
|---|---|---|---|---|
| **短想法 thought** | 不让念头溜走 | ≤ 500 字 | 高频 | 门槛最低；agent 可直接从对话里替你发布；可被“晋升” |
| **笔记 note** | 消化输入、沉淀知识 | 不定 | 随时 | **常绿**：可反复更新；用双链互相引用，渲染“被引用”；对应你想做的知识库 |
| **问答 qa** | 回答一个具体问题（知乎式） | 500–3000 字 | 不定 | 标题是一个**问题**，正文是“我现在的回答”；允许迭代，修订可见 |
| **随笔 essay** | 完整论证一个观点 | 1500–5000 字 | **每周一篇** | 有论点、论据、反方；是“逻辑论述能力”的主要训练场 |
| **页面 page** | 站点固定页 | — | 稀少 | about / now / uses…（**内容待你提供**） |

“生活”不是独立类型，而是**话题（topic）**：任何类型都可以挂 `topic: 生活`。
**晋升（promote）** 是一等操作：agent 可以把“本周的 3 条短想法”合并成一篇随笔草稿，并在 frontmatter 里记录 `promotedFrom`——这直接服务于你“输出训练”的目标。

> **规划域（经济/人生）不属于这条阶梯**，它是结构化数据而非文章，见 3.4 与第 8 章。

### 3.2 话题体系

受控词表（5–8 个，可演进）+ 自由标签：

| 话题 topic（受控） | 对应你原文 |
|---|---|
| AI 与使用反思 | “个人关于 ai 使用的思考、反思” |
| 时事评论 | “关于时事的评论” |
| 学习笔记 | “一些学习笔记” |
| 人生观与世界观 | “人生观、世界观的思考” |
| 自我理解 | “对于自我的理解、输出” |
| 生活 | “生活” |
| 工作与成长 | 你的第一份 offer 之后会自然出现的话题（建议预留） |

另有**系列 series**（带顺序的专题，如“AI 使用反思”）。话题与系列都是 frontmatter 字段，不是目录结构，所以随时可调。

### 3.3 “知乎式问答”与观点演化（你想形成自洽世界观的核心机制）

你要的不只是“发文章”，而是**在持续输出中把观点打磨到自洽**。这件事需要网站帮你“记住你怎么想过”。设计如下（借鉴 Gwern 的 *Epistemic status / Confidence*、Matuschak 的 *Evergreen notes*，但落地成你自己的轻量版本）：

| 机制 | 字段 | 站点上怎么呈现 | 为什么 |
|---|---|---|---|
| **问题驱动** | `question`：这篇在回答什么问题 | 文章顶部显示问题；站点有“问题索引”页：我在回答什么 | 把“文章流”变成“问题地图”；知乎式问答天然适配 |
| **一句话论点** | `thesis` | 文章头部的论点行（≤ 60 字） | 强迫自己先想清楚再写；也是 OG 图/视频脚本的钩子 |
| **立场标注** | `stance`：暂定 / 倾向 / 确信 / 重新思考中；`confidence`：1–5 | 头部一个克制的小标记 | 允许“不确定”，降低完美主义，也诚实 |
| **修订可见** | `revisions[]`（`date` + `note`：为什么改） | 文末“我的看法如何变化”时间线 | 不悄悄改文章；Git 历史提供底座，站点渲染成演化史 |
| **论证结构（可选）** | `claims[]`、`counterpoints[]` | 阶段 1 只存字段，**阶段 5** 才做可视化“世界观地图” | agent 能协助抽取；字段成本低，先存起来 |
| **成熟度** | `maturity`：成长中 / 成形 / 常绿 | 列表里的小标记 | 允许公开“半成品”，进一步降低发布门槛 |

> 这些字段**都是可选的**。一篇短随笔可以只有标题和正文；机制是脚手架，不是门槛。

### 3.4 内容域的分离（回应“经济人生规划建议和博客文章分开”）

站点内部分为五个**互不共享存储**的域，域之间只通过 ID/链接引用：

| 域 | 内容 | 存储 | 谁写入 | 变更节奏 |
|---|---|---|---|---|
| **Editorial 文章域** | thought / note / qa / essay / page | Git（MDX） | 你 + agent | 周 |
| **Plan 规划域** | 账本快照、里程碑、五年路线、人生规划 | Git（仅**已公开**的快照 JSON） | **经济规划项目**（独立）→ 契约 | 周 / 月 |
| **Engagement 互动域** | 评论、点赞、留言、阅读计数 | Supabase Postgres | 访客 | 实时 |
| **Distribution 分发域** | OG 图、视频、newsletter、社媒文案等派生物 | 对象存储 + 元数据 | agent | 随发布 |
| **Ops 运营域** | 令牌、审计日志、配置、审批记录 | Supabase | 系统 | 实时 |

**编年史（Timeline）是读模型**，不是第六个域：它聚合“人生事件 + 里程碑 + 关联文章”，只读展示。

### 3.5 写作前端与站点的关系（回应“Obsidian 还是 Notion”）

结论：**你不用现在决定。** 站点只认“内容契约”（Markdown + frontmatter，见附录 A），Obsidian 与 Notion 都只是把内容送进契约的**写作前端**：

```
Obsidian vault（私有知识库） ─┐
                              ├─► agent 整理 ─► 内容契约(MDX) ─► Git ─► 站点
Notion（未来可选）           ─┘
```

- **知识库的主场在 Obsidian（私有）**，站点只发布你标记 `publish: true` 的笔记；这样“沉淀知识库”和“公开发表”是同一份素材的两个层级，而不是两件事。
- agent 负责**格式转换**：`[[双链]]` → 站内链接（按 ID 解析）、`![[图片]]` → 上传媒体并回填、`> [!note]` 提示块 → `<Callout>`、`==高亮==` → `<mark>`、`#标签` → frontmatter。转换规则写进附录 A 与 agent 手册。
- 将来想换 Notion：只需多写一个“Notion → 契约”的导出器，站点与发布管线**一行不改**。

### 3.6 作者声音保护（agent 改稿的“宪法”）

你的流程是“你写 → agent 整理修改 → agent 发布”。风险在于 agent 悄悄改变你的观点或口吻。规程如下：

| 级别 | agent 可做的事 | 默认权限 |
|---|---|---|
| **L0 校对** | 错别字、标点、格式、死链 | 自动 |
| **L1 结构** | 调整段落顺序、加小标题、生成摘要/论点行/标签/封面 alt | 自动，**但出 diff** |
| **L2 表达** | 改写句子以求清晰、统一术语 | **需你批准**（出 diff） |
| **L3 扩写** | 补充论据、新增段落 | **默认禁止**；仅当你明确要求 |

铁律：

1. **不得改变任何主张与立场**；拿不准就在草稿里加 `agent_note` 提问，而不是自作主张。
2. **原稿不可变**：你交出的原稿先被原样存档（`raw`），发布版永远可以和原稿 diff。
3. **每次改动都落成可审阅的 diff**，并附一段 `agent_note`：改了什么、为什么。
4. **披露**：每篇记录 `assist`（none / proofread / structure / translate），站点以不显眼的方式显示“编辑协助：AI 整理”（可配置；对时事类内容建议保持开启）。
