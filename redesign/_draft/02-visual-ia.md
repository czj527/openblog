## 4. 视觉与体验

### 4.1 总概念：「窗」「桌」与「工作台」

> **窗外是世界，桌上是思考，工作台是动手的地方。**

公开站只有两个页面家族：**窗 Window** 与 **桌 Desk**。**工作台 Workbench** 不是第三个公开页面家族，而是作者与 agent 的私有工作层；三层按可见性与职责划分：

| | **窗 Window** | **桌 Desk** | **工作台 Workbench（私有）** |
|---|---|---|---|
| 页面 | 首页 `/` | 其余所有公开页面 | `/workbench`（受保护，不进入公开导航） |
| 可见性 | 公开 | 公开 | 私有（登录；默认 `noindex`，不进 sitemap / llms.txt） |
| 目的 | 让人停下来看，带起情绪 | 让人读懂、查到、找到 | 让作者和 agent 处理任务、周计划、项目进度、草稿审阅与公开投影 |
| 视觉 | 全屏摄影级场景 + 实时天气，几乎没有文字 | 安静的中性色画布，信息优先 | 工具化、低噪声、密度高于 Desk；无窗景装饰 |
| 动效 | 丰富但克制（雨、雪、雾、光、视差） | **零装饰性动效**，只有功能性过渡 | 仅功能性反馈；不做叙事性动效 |
| 技术 | 静态底图承担 LCP，WebGL 渐进接管 | 纯静态/ISR，无 WebGL | 私有应用；鉴权 + 受控 API；不纳入公开 CWV 预算 |
| 对应你的话 | “空荡的欢迎页……不要阻碍壁纸的视觉表达” | “回到博客应有的信息传达上” | “所有博客相关操作都 agent 原生” + “后台管理繁琐” |

Window 与 Desk 之间用一条**窗沿（Sill）** 衔接：每个桌页顶部是一条取自窗景的静态切片（轻度模糊、带季节色偏），向下渐隐进桌面底色；滚动后收成 56px 的紧凑顶栏。
这样桌页天然带着“此刻的天气”，却不牺牲阅读。从窗进入桌时，窗的画面缩成窗沿（共享元素过渡，见 4.8）。

Workbench（见 4.10）与公开叙事无关：不使用窗→桌共享元素过渡，也不出现在公开导航里；它沿用 Desk 的中性色令牌，但不换季节皮肤。公开成果只有经过显式投影才会出现在 Desk（必要时 Window）。

> **四季 × 天气在这里的位置**：它是**场景**，不是**换肤**。旧站的做法是季节直接覆盖主色、天气再微调强调色，结果每屏都有装饰、对比度还不够（旧站浅色四季主色实测只有 2.63–2.94:1，`01-legacy-digest.md` §1.2）。新设计里，**季节与天气只发生在窗里和窗沿里，UI 的中性色与对比度永远固定**；Workbench 不参与季节换肤。

### 4.2 窗（首页）规格

**一屏，不滚动**（`100dvh`，`overscroll-behavior: none`）。除下列元素外，不出现任何文字：

| 元素 | 规格 | 说明 |
|---|---|---|
| **场景** | 底图（AVIF，承担 LCP）+ WebGL 图层（LCP 之后接管）：交叉淡化、雾、云影、雨滴窗/雨/雪、季节粒子、遮罩微动、轻视差 | 详见 4.3 与附录 C |
| **顶栏** | 左：窗标（四格方窗图形，暂代站名）；右：写作 · 规划 ·（关于）· 中/EN · 窗外 | 13–14px；无底板；前景色按底图亮度自动取深/浅；仅靠渐隐 scrim 保证可读 |
| **跳转按钮** | **MVP 只放 1 个**：「写作」；规划页上线后加第 2 个「规划」。液态玻璃，位于“留白带”（约 40–46% 高度） | R3“一两个”；按钮是**窗玻璃上的物件**，折射取自背后的底图 |
| **“此刻”HUD** | 左下：`城市 · 节气/季节 · 天气 · 时间`，12px 等宽数字；点击展开「窗外」面板 | 同时是场景的无障碍文字描述（给读屏用） |
| **「窗外」面板** | 小型玻璃浮层：手动选择季节/天气/时段、「回到真实」、暂停动效、雨滴强度；底部署名天气数据来源 | 手动覆盖只存 localStorage，不上报 |

**交互细节**：

- 指针视差 ±6–8px（触屏用陀螺仪，需授权，默认关）；玻璃按钮悬停时折射增强、按下有水滴涟漪。
- 起雾/雨天可“擦窗”（仅桌面 hover，30 秒无操作自动复原，可在面板关闭）。
- 入场顺序：低清占位 → 底图淡入 600ms → 顶栏/HUD 延迟 300ms 淡入 → WebGL 在 LCP 后以 600–1200ms 渐入。
- **降级阶梯**：`prefers-reduced-motion` / 无 WebGL2 / 省流模式 → 一张静态好图 + CSS 玻璃；永远不弹错误。

**MVP 首页的“空”是有意的**：没有口号、没有头像、没有自我介绍（R11）。窗标用抽象图形占位，页面 `<title>` 暂用域名，待你提供站名后替换。

### 4.3 主题引擎：四季 × 天气 × 时段（详细映射见附录 C）

**状态**：`WindowState = { season, weather{type, intensity, wind}, tod{phase, sunAlt}, source }`

| 维度 | 取值 | 数据来源 |
|---|---|---|
| season | 春 / 夏 / 秋 / 冬（可选叠加 24 节气作文化标注） | 真实日期；气象季节 3–5 / 6–8 / 9–11 / 12–2；**边界前后 ±7 天做底图平滑混合**，避免一夜入冬 |
| weather | **4 主类**：晴 · 阴 · 雨 · 雾；**2 变体**：雪（寒冷时的降水）· 雷雨（雨的强化） | 方向是作者所在地真实天气；MVP 先用占位天气 + 手动预览，真实 provider 与城市待定（D-010）；失败回退到气候学伪随机 |
| tod | 夜 · 黎明/黄昏（蓝调、黄金）· 白天 | SunCalc 太阳高度（服务端算作者坐标），平滑权重避免整点跳变 |
| source | 真实 live / 气候兜底 climatology / 手动 manual | 优先级：manual > live > climatology |

设计要点：

1. **“场景是想象的，天气是真的。”** 底图是一个虚构的温带山湖谷地，不是你所在城市的实景；季节、天气、昼夜与你此刻的真实天空**押韵**。接入真实 provider 后，HUD 写出真实城市与天气，访客知道“这是你窗外此刻的世界”；MVP 先用占位天气和手动预览，不伪造实时数据。
2. **不做 56 套组合。** 底图只按 (季节, 昼夜) 取（MVP：4 季 × {日, 夜} = 8 张；黎明/黄昏由调色与窗光增强得到；v2 再补 8 张）；天气全部由着色器叠加。这样资产量可控，组合不会失控。
3. **干净底图原则**：雨丝、雪花、落叶由着色器画，底图只负责“湿、阴、雾、积雪”的氛围。
4. **克制系数 0.7**：所有天气效果强度出厂乘 0.7（雨滴窗默认“中低”）；你和访客都可以在「窗外」面板调节。理由：强效果会压过底图与文字，也是“花哨”的来源。
5. **UI 令牌只受少量参数驱动**：`--hero-scrim-top/bottom`（可读性渐隐）、`--fg`（前景深浅，由底图上部平均亮度决定）、`--glass-tint`（季节色 8–12%）、`--accent`（仅用于窗光/小高光）。**UI 文字对比度固定 ≥ 4.5:1，不随季节漂移。**
6. **天气源可替换**：`WeatherProvider` 接口隔离。起步用 Open-Meteo（免费层仅限非商业，数据 CC BY 4.0 需署名）；**一旦上广告或其他商业化，必须改买商用订阅或换源**（见第 9、14 章）。全站每 15 分钟最多 1 次上游请求，与访客数无关。
7. **隐私**：不调用定位、不做 IP 定位；天气按作者固定坐标（城市级，精度 0.1°）服务端获取，全站共享缓存。

### 4.4 窗的资产生产线

| 阶段 | 产物 | 要点 |
|---|---|---|
| ① 美术方向 | 《窗外》方向稿（`_brief/ART-DIRECTION.md`） | 摄影级写实；一盏小暖窗；同一场景全年复用；AI 味黑名单 |
| ② 母版 | 3840×2160，生图模型 + 编辑接口保持构图一致 | 母版不进仓库（对象存储/本机）；每张记录提示词、参数、自检结论 |
| ③ Web 版 | AVIF 2560w（桌面 ≤ 240KB）/ 1280w（移动 ≤ 70KB），LQIP ≤ 1KB | **4K 只做 poster 与母版，GPU 纹理最高 2560**（4K 多占 24.5MB 显存，肉眼在全屏 16:9 下几乎看不出） |
| ④ 遮罩 | foliage / water / sky 三通道合成一张 RGBA | 离线用 SAM 2（Apache-2.0）分割；运行时做 1–3px 的“呼吸式”微动 |

### 4.5 桌（二级页）规格

**版心：不是居中窄栏。** 你在旧原型评审里点过名——“太居中了，左右两侧留白太多”。桌页用**左对齐的三栏阅读布局**，让两侧有事可做：

```
≥1280px：[目录 200px] 48px [正文 680px] 48px [语境栏 240px]
         ↑ 左栏：TOC、系列导航    ↑ 右栏：论点 / 立场 / 修订 / 被引用 / 旁注
<1280：  语境栏并入正文末尾（旁注变脚注）
<1024：  目录收成顶部「目录」折叠
<640 ：  单栏，20px 边距
```

- 正文 680px ≈ 每行 38–42 个汉字（17px），符合中文阅读舒适区。
- **右栏的“语境”承载本站独有的东西**：一句话论点、立场与成熟度、问题、修订时间线、被引用（backlinks）、系列位置。没有这些内容的文章，右栏退让给旁注，绝不空摆装饰。

**排版**（🟡 数值待《参考站拆解》校准，下为工作值）：

| 项 | 中文正文 | 英文正文 | 说明 |
|---|---|---|---|
| 正文 | 17px / 1.8 | 16px / 1.65 | 中文行高更大；`font-feature-settings` 开启 `tnum` 用于数据 |
| H1 | 40 / 1.2，字重 600 | 同 | 字阶步进约 1.25（大三度），至少 5 档 |
| H2 / H3 | 26 / 1.35；20 / 1.45 | 同 | 不用下划线装饰；靠字号与留白分层 |
| 元信息 | 13–14px，等宽数字 | 同 | 日期、阅读时长、立场标记 |
| 字重 | 仅 400 / 500 / 600 | 同 | **中文必须用 Web 字体并子集化**（Windows 自带中文字体只有 400/700，中间字重会跳粗） |

**间距**：4px 基准，阶梯 `4·8·12·16·24·32·48·64·96·128`；垂直节奏 8px。
**色彩**：中性色阶（OKLCH，色相≈250、彩度≤0.015），浅色“纸”与深色“夜”两套，默认**跟随窗的昼夜**（可手动固定）；底色不用暖黄/米白（回避“暖色衬线”模板味）；**一个强调色，随季节微变，只占不到 3% 的像素**（焦点环、链接悬停、选中高亮、图表高亮）。
**层级**：发丝线（1px，8–12% 透明度）+ 留白；**不做卡片阴影**，只有浮层有一档阴影；圆角仅 `2 / 6 / 12 / 999` 四档。
**列表**：写作索引用**排版行**（日期｜标题｜摘要｜标记）+ 发丝分隔，不用缩略图卡片网格。

**核心组件**（桌）：窗沿 · 顶栏（紧凑）· 文章头（问题/标题/论点/元信息）· 目录 · 正文排版（标题、引文、列表、表格、图、脚注→旁注、代码块）· 立场/成熟度标记 · 修订时间线 · 被引用 · 系列导航 · 评论与反应 · 页脚（含天气数据署名）· 搜索 · 语言切换 · 明暗切换。

### 4.6 字体系统（🟡 待《参考站拆解》与字体授权核验）

约束与方向（具体字体在“样张”里定，不凭印象选）：

1. **全站以无衬线为主**（回避“重复的衬线”）；衬线至多用于引文，且每页 ≤ 1 处。
2. **拉丁字体**：中性偏人文的现代无衬线 + 配套等宽字体（候选：Geist / Inter 系；以《参考站拆解》对 Linear、Apple 的实测为准）。
3. **中文字体**：HarmonyOS Sans SC / MiSans / 阿里巴巴普惠体 / Noto Sans SC 中择一（以授权条款核验为准，见 `04a-hosting-network-icp.md`）；**必须按 unicode-range 分片、`font-display: swap`、只预载首屏字重**，首屏字体 ≤ 80KB（桌面）/ 60KB（移动）。
4. 字重只用 400 / 500 / 600；展示级文字不使用 700 以上。

> StyleKit 的“编辑杂志风 Editorial”正好是衬线标题 + 暖色纸感的模板示例；它只用于对照“哪些不要采用”，不作为本站默认方向。

### 4.7 “反 AI 味”清单（可检查）

“AI 味”不是审美玄学，而是一组**可观察的特征**。每次改版/评审逐条打勾：

| # | AI 味特征（来源） | 解药（可检查） |
|---|---|---|
| 1 | 衬线大标题 + 暖纸白底的“编辑风”模板（v1-A 被否） | 全站无衬线为主；底色冷中性；衬线仅引文、≤ 1 处/页 |
| 2 | 渐变光晕、极光、虹彩渐变字（v2 被否，v3 存疑） | **窗之外禁止渐变背景与渐变字**；窗里的光来自摄影，不来自 CSS |
| 3 | 卡片网格 + 软阴影 + 大圆角（shadcn 默认皮肤） | 列表用排版行 + 发丝线；阴影只给浮层；圆角 ≤ 4 档 |
| 4 | 居中窄栏 + 两侧大留白（样板站通病） | 左对齐版心；两侧栏承载目录与语境 |
| 5 | emoji 当图标/粒子（旧站季节粒子） | 统一线性图标（1.5px 描边）或不用图标；粒子只在窗里且是“物理的”（雨、雪、落叶） |
| 6 | 一屏多个“亮点”：星星、渐变字、3D tilt、打字机（旧站 Hero） | 每页最多 **1 个**视觉焦点；桌页 0 个装饰动效 |
| 7 | 一个字号节奏走到底、字重全是 500/700 | 至少 5 档字号、步进 ≥ 1.2；字重只用 400/500/600 |
| 8 | 炫酷仪表盘、假数据图表 | 图表只用真实数据；单色 + 1 个强调色；数字等宽 tabular |
| 9 | 套话文案（“欢迎来到我的数字花园 ✨”） | 微文案短、具体、克制；前期不写口号（R11） |
| 10 | 塑料般过度平滑的图、正中对称构图、发光物（AI 生图） | 底图过“硬性规则 + 黑名单”，统一调色加颗粒；构图不居中 |
| 11 | 季节换掉主色 → 高饱和撞色、对比度崩塌（旧站 2.63–2.94:1） | 季节只改窗内与窗沿；UI 中性色固定；文字对比度 ≥ 4.5:1 |

> 这份清单会在“参考站拆解”（`02-reference-teardown.md`）完成后，用对 Linear / DeepSeek / Artificial Analysis / Apple / StyleKit / OpenColorful 的**实测证据**再校一遍。
> StyleKit 参考：https://www.stylekit.top/zh（核验 2026-10-26）只用于系统层参考——借鉴字号、间距、配色和博客版式的组织方式；不直接复用模板、提示词或代码，不采用其“编辑杂志风”的衬线 + 暖色默认样式。具体原则见 `_brief/workbench-boundary.md` §10。

### 4.8 页面过渡：从「窗」到「桌」

- **首选**：共享元素过渡——窗的 hero 容器与桌页窗沿使用同一 `view-transition-name`；点击「写作」时，带当前帧的窗缩成窗沿，桌页内容 240ms 淡入。Next.js 16 的同文档导航可用；Firefox 不支持**跨文档**过渡，但同文档导航不受影响（Firefox 144 起支持同文档）。
- **降级**：不支持或 `prefers-reduced-motion` → 120ms 交叉淡化 + 4px 上移；不做横向滑动。
- **已知坑**：Next 16.3 下 class 形式的 `enter/exit` 动画不触发（react#37614），只用 `name` 共享元素；Safari 对 WebGL 图层的过渡快照不稳定，需真机验证，失败则改用“poster 快照 + 立即隐藏 canvas”。
- **Workbench**：不使用窗→桌共享元素过渡；先完成鉴权检查再渲染，避免私有内容在过渡中闪现。
- **Composition / D7 历史证据（2026-10-26，已归档）**：`archive/prototypes/composed-prototype.html` 曾把持久 Window 场景、取自同一 poster 的窗沿、Desk 公开读模型和 Workbench 私有工作层组合到同一份合成状态。2026-10-27 用户否决组合原型，原型已归档；这段记录只说明当时尝试过哪些体验交接和状态语义，**不是当前视觉基线**，也不替代真实认证、存储、MCP 或跨浏览器生产验证。

### 4.9 性能、无障碍与动效预算

| 项 | 桌面 | 移动 | 备注 |
|---|---|---|---|
| 首屏字节（不含 WebGL） | ≤ 350KB | ≤ 190KB | 含 HTML/CSS、字体、poster、启动 JS |
| WebGL 块（LCP 后加载） | ≤ 45KB gz | ≤ 45KB gz | 原生 WebGL2，不引入 three.js（最小包实测 129.6KB） |
| LCP（4G，中端机） | ≤ 2.0s | ≤ 2.5s | poster 是 LCP；WebGL 绝不抢 LCP |
| GPU 纹理常驻 | ≤ 45MB | ≤ 12MB | 桌面 2560 纹理，移动 1280 纹理 |
| 帧时间 | ≤ 6ms@60fps | ≤ 12ms@30fps | 运行时按前 60 帧 p95 自适应分 4 档 |
| 桌页 LCP / JS | ≤ 1.5s / ≤ 60KB gz | 同 | 纯静态 + 少量岛屿 |
| CLS | < 0.02 | < 0.02 | 广告位预留尺寸（第 9 章） |

> 以上是**预算而非实测**（实测需真机 4G 档：Windows 集显笔记本、iPhone 12/13、Android 中端、iPad）。Workbench 是私有工具页，不纳入公开 LCP/CWV 预算；其可用性底线由 D6 单独验收。

**无障碍底线**：文字对比度 ≥ 4.5:1（亮底图上靠渐隐 scrim + 按钮自带底色，不只靠 text-shadow）；`prefers-reduced-motion`、`prefers-reduced-transparency`、`forced-colors` 三件套全部处理；焦点环 2px 实线；点击区 ≥ 44×44px；闪电 ≤ 每分钟 2 次且不超过 3Hz（光敏性），`reduced-motion` 下关闭；canvas `aria-hidden`，由 HUD 文字提供场景描述；提供“暂停动效”开关（持久化）。

### 4.10 工作台（Workbench，私有层）

**定位**：作者与私人助理 agent 共用的私有工作层，不是公开页面、不是站内编辑器、不是第六个公开内容域。它承载个人任务、每周计划、项目进度、审阅/批准和公开投影；体验上是低噪声、可恢复、清晰下一步的「避风港」，但安全感来自隐私与秩序，不来自暖色装饰。写作仍在 Obsidian / Notion；任务/周计划/项目是私有执行数据，不等同于 Plan。

**视觉与体验**：低噪声、低饱和、少装饰；用清晰的层级、状态和“下一步”提示提供安全感，不用暖色/毛毯/壁炉式治愈模板，也不做装饰性动效。

**最小 IA（推荐）**：

```
/workbench
├─ 本周：周计划、周内节奏、下一步
├─ 任务：状态、优先级、下一步
├─ 项目：阶段、进度、下一节点
└─ 审阅：待审阅 / 待批准 / 待投影 / 已撤回 + 投影预览
```

| 区域 | 职责 | 边界 |
|---|---|---|
| 本周 | 周计划、周内节奏和清晰下一步 | 只显示结构或合成 fixture；不填真实任务 |
| 任务 | 状态、优先级、下一步 | 私有执行数据；不进入 Editorial，也不写入 Plan 账本 |
| 项目 | 阶段、进度、下一节点 | 不替代 Plan 的公开规划；不自动公开 |
| 审阅/投影 | diff、批准、字段白名单、投影预览 | 来源域仍是 source of truth；投影可撤回 |
| 状态/审计 | 展示 Ops 审计与失败原因 | 审计写入只在 Ops；Workbench 不可改写 |

**私有默认与公开投影**：

- `/workbench` 必须鉴权；未登录不返回工作项内容；不进入公开导航、`sitemap.xml`、`llms.txt`。
- 新建工作项、任务、周计划和项目默认 `private`；公开投影必须同时满足“已批准 + 字段白名单 + 有投影权限 + Ops 记录”。
- 投影是单向、绑定来源版本、可撤回的公开动作；不是 Workbench 与 Desk 的双向同步。
- 来源域仍是唯一 source of truth：Editorial 的 MDX/Git、Plan 的版本化 Ledger Snapshot、Ops 的审计记录；任务/周计划/项目属于 Workbench 私有执行存储，不是公开内容域。
- 原始任务列表、周计划明细和项目内部进度不直接公开；只有经批准的公开摘要/里程碑可以投影。
- 空状态只展示结构（如“暂无任务/项目/待处理”），不生成假文章、假金额、假任务或假项目（R11）。

**Agent 对等**：人类在 Workbench 能做的每个动作，都有等价的类型化接口（MCP / CLI / REST）；UI 只是薄客户端。读取私有内容、改变审阅状态、触发公开投影、管理令牌分别授权；L2 表达修改和财务字段投影必须人工批准。

> 完整边界、结构性字段草案和 D6 验收表见 `_brief/workbench-boundary.md`。

### 5.2 导航

- **窗**：顶栏极简（4.2）。
- **桌**：紧凑顶栏——左窗标（回首页），中间/右侧 `写作 · 规划 · 时间线 · 关于`（**未上线的项不显示**），右侧 搜索 · 语言 · 明暗。
- **Workbench**：不进入 Window/Desk 公开导航；只允许独立、受鉴权保护的私有入口，且不出现在页脚、sitemap 或公开搜索。
- MVP 只显示 `写作`；其余随阶段出现。导航项的出现本身就是站点生长的可视化。

### 5.3 空状态与未就绪（R11 的落地）

内容为空时是设计的一部分，不是 bug：

| 场景 | 处理 |
|---|---|
| `/writing` 无文章 | 极简空状态：沿用桌的排版，一行中性文案“暂无文章”，**不写**鼓励语/口号 |
| 英文页无译文 | `/en/writing` 只列已翻译文章；顶部一行“更多文章仅有中文版”并链回 zh |
| 规划域无快照 | `/plan` 不进入导航（页面未上线） |
| 未填写个人资料 | `/about` 不上线；窗标代替头像；`<title>` 用域名 |
| Workbench 无任务/项目/待处理项 | 只显示“暂无任务/项目/待处理”与结构说明；不生成假草稿、假任务、假项目或假金额，不显示鼓励语/口号 |

### 5.4 SEO 与分享的基础约定

每个可索引页：唯一 `<h1>`、规范 `canonical`、`hreflang` 成对、`BlogPosting` JSON-LD、自动生成 OG 图（标题 + 论点行 + 当季窗景切片）；`noindex` 用于预览与草稿。Workbench、私有预览和未投影工作项一律 `noindex`，且不进入 `sitemap.xml`、`llms.txt` 或公开搜索；只有公开投影后的 Desk 页面才有 `canonical`。细节见第 9 章。
