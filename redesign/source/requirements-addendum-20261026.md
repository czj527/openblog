# 需求增补：工作台与避风港定位

> 日期：2026-10-26
> 来源：用户在 openblog redesign 设计讨论中的新增要求。
> 地位：这是 `source/original-requirements.md` 之外的增补，不改写原文；需要与原文一起阅读。若两者冲突，先回到用户确认记录重新决策。

## 1. 工作台能力

用户补充：

> 我们的原博客存在一个个人每周规划的表格，实际上，我也希望我的博客能够承载一些“工作台”的功能，例如我在博客里规划任务，每周计划，项目进度等等。

本句将工作台能力加入设计验证范围，至少需要验证：

- 个人任务的规划、状态和下一步；
- 每周计划与周内节奏；
- 项目进度、阶段和下一节点；
- 与文章草稿、Agent 审阅和发布状态的关系。

这项能力不是新的文章类型，也不自动等同于经济规划。经济规划仍由独立项目产生 Ledger Snapshot；工作台只承载执行视图和受控动作。

## 2. 避风港 / 自我实现的体验定位

用户补充：

> 这个博客应该不只是一个“温暖小窝”，他应该是一个“在外部嘈杂环境的情况下，一个安全，舒适，平静，能让我静下心来，思考、规划、安心的做一些事的地方，有些寒冬里温暖被窝的感觉，不过那是小时候关于安全感的体会，现在我们需要是关于工作，自我实现与价值的体会”

这段话扩展“个人小窝”的体验语义：安全感不只来自视觉温度，也来自私密默认、低噪声、可恢复、清晰下一步和不被外部打扰的工作秩序。它不是要求加入壁炉、毛毯、暖米色或装饰性治愈文案。

## 3. 美学参考边界

用户再次强调：

- 美学是重要要求，设计需要有自身思考和完整体系；
- 反对 AI 味、廉价和粗糙感；
- 参考站点：<https://www.stylekit.top/zh>。

当前采用的参考规则是：只借鉴 StyleKit 在字号阶梯、间距、发丝线、信息层级和组件状态组织上的方法；不直接复制其模板、提示词、代码或未核验的设计 token，不把衬线 + 暖色编辑模板当作 openblog 默认方向。

## 4. 当前设计含义

- 公开站继续由 Window（情绪）和 Desk（信息）组成；
- Workbench 是作者与私人助理 Agent 共用的私有工作层，不进入访客导航；
- 公开成果只能由显式批准、字段白名单和来源版本绑定的投影产生；
- 这次增补新增 D6 Workbench 设计门；D6 通过前不进入生产实现；
- 原型只能使用结构占位和合成 fixture，不填真实任务、个人资料、经历或财务数字。
