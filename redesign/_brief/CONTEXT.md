## 5. 主 agent 的工作假设（可以被证据推翻——请明确指出）

- **H1 窗与桌**：首页 =「窗」（真实季节/天气/时段驱动的沉浸式场景，液态玻璃按钮就是窗玻璃上的东西）；二级页 =「桌」（安静、信息优先，顶部有一条取自「窗」的窗沿过渡）。
- **H2 主题引擎**：主题状态 = (season, weather, timeOfDay)。数据源 = 作者所在地真实天气（如 Open-Meteo）+ 日期 + 太阳高度；失败则用气候学兜底；访客可手动覆盖。UI 色彩由少量参数（色相/彩度/明度/雾度/粒子类型）驱动，而不是 24 套手工主题。
- **H3 渲染**：AI 生成的摄影级底图（季节 × 时段）+ 轻量 WebGL 着色器（窗玻璃雨滴、雪、雾、云影、视差）；不引入完整 three.js 除非必要。LCP 靠静态底图，WebGL 渐进增强。
- **H4 内容与写作工具解耦**：站点只认统一的内容契约（Markdown + frontmatter schema）；Obsidian / Notion 都只是可替换的「写作前端」。
- **H5 Agent 对等**：人类后台能做的每件事都有同等的类型化接口（MCP / CLI / REST）；给人用的 Workbench 只是同一 API 的薄客户端；发布走「草稿 → 预览 → 确认 → 发布」，可按内容类型配置为自动。
- **H6 财务解耦**：本站只消费一个版本化的「Ledger Snapshot」契约，不关心数据怎么来（支付宝导出、Beancount、Notion 都行）。
- **H7 国际化**：zh-CN 为源语言，en 一等公民；翻译由 agent 完成并标注「机翻 / 已人工审」。
- **H8 去后台化**：「后台管理繁琐」是旧站痛点 → 目标是几乎不需要人进后台；人只需要「审阅与批准」。
- **H9 工作台与投影**：Window（公开情绪）/ Desk（公开信息）/ Workbench（私有工作）三层；Workbench 默认私有、默认不进公开导航与索引，公开成果必须经显式「投影」动作进入 Desk（必要时 Window），并可按来源版本撤回。Workbench 承载个人任务、每周计划、项目进度等私有执行数据，但不复制 Editorial / Plan / Ops 的 source of truth；任务/周计划/项目不是新的文章类型，也不等同于 Plan。体验目标是低噪声、可恢复、清晰下一步的私有「避风港」。验收门为 D6，细则见 `_brief/workbench-boundary.md` §9。
- **H10 参考原则**：StyleKit（https://www.stylekit.top/zh，核验 2026-10-26）只作系统层参考：借鉴字号、间距、配色和博客版式的组织方式；不直接复用模板、提示词或代码，不采用「衬线 + 暖色」的编辑模板默认样式。详见 `_brief/workbench-boundary.md` §10。

## 6. 工作规则（必须遵守）

1. **语言**：报告用中文（技术名词保留英文原文）；文件名/代码用英文。
2. **证据标准**：每条事实性结论附 **来源 URL + 核验日期**（核验日期以当前任务书为准；本文件的历史基线是 2026-10-23）。明确区分「已核验事实 / 社区经验 / 你的推断」。
   价格、版本、政策、API 能力以**官方页面**为准。查不到就写「未查到」，**严禁编造**。
3. **不替用户拍板**：需要用户决定的事写进报告末尾「需用户决策的问题」（含你的推荐项与理由）。不要阻塞等待。
4. **文件范围**：只写你被分配的路径；不要修改 `redesign/` 之外的任何文件（`D:\openblog\_tools\`、`D:\openblog\_assets\` 除外且仅限任务书允许时）；不要改旧仓库文件。
5. **密钥**：任务书中给你的 API Key 只能通过环境变量或命令行参数临时使用，**绝不写入任何文件**（脚本、日志、报告、截图文件名都不行）。报告里不得出现密钥。
6. **联网检索**：优先内置 WebSearch / WebFetch。若不可用，用 DeepSeek 搜索/抓取 API：
   文档 https://api-docs.deepseek.com/zh-cn/guides/search ；
   `POST https://api.deepseek.com/v1/tools/search`（JSON：`{"query": "..."}`），`POST https://api.deepseek.com/v1/tools/fetch`（抓取页面为 Markdown）；
   结果含 `authority`（0–4）与 `rerank_score`（0–3），优先 authority ≥ 3；支持 `site:` `lang:` `after:` `before:` 语法。每个 agent 的搜索/抓取调用 ≤ 80 次。
7. **浏览器**：共享的 Playwright MCP 浏览器同一时刻只能一个 agent 用——只有任务书明确授权的 agent 才可使用。
   其他 agent 要截图/测试页面，请用 `D:\openblog\_tools\shot\shot.mjs`（若存在，用法见同目录 README），或在自己的临时目录里 `npm i playwright-core` 并用 `channel: 'msedge'`（Windows 自带 Edge，无需下载浏览器）。
8. **质量自检**：交付前通读自己的报告，删掉空话；每个「推荐」都要能回答「为什么不是另一个」。
9. **最终回复格式**（≤ 250 字）：① 产出文件路径；② 3–6 条最重要的结论；③ 仍需用户决策的点。**不要把报告全文贴回来。**
