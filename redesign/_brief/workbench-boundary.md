# Workbench 边界（私有工作层）

> 状态：已批准方案的结构化落地草案（2026-10-26）。本文定义 Workbench 的定位、私有默认、公开成果投影、与 Editorial / Plan / Ops 的边界以及 D6 设计门；**不是最终数据库 schema，也不是实现规格**。
>
> 需求来源：Workbench 属于 2026-10-26 批准方案中的需求增补，不在 `source/original-requirements.md` 原文条目内。原文仍是基础权威需求源；增补原文已落盘为 `source/requirements-addendum-20261026.md`，本文件与 `_brief/CONTEXT.md` 的 R13 负责归一化和边界说明。

## 1. 一句话

**Workbench 是作者与私人助理 agent 共用的私有工作层：在这里规划任务、每周计划与项目进度，处理草稿/审阅/发布，并把经批准的公开成果投影到 Window / Desk。工作默认留在私有域，只有经过审阅、批准并按字段白名单投影的成果，才进入公开面。**

它不是第三个公开页面家族，不是站内 CMS，也不是新的公开内容域。

## 2. 三层模型

| 层 | 可见性 | 职责 | 入口 | 明确不是什么 |
|---|---|---|---|---|
| **Window 窗** | 公开 | 情绪、欢迎、四季 × 天气场景 | `/` | 不显示私人状态、草稿、金额或工作项 |
| **Desk 桌** | 公开 | 阅读、索引、规划展示等信息传达 | `/writing`、`/plan/*` 等公开路由 | 不是 Workbench 的镜像；不展示未投影草稿 |
| **Workbench 工作台** | 私有（登录） | 任务/周计划/项目/草稿审阅/公开投影/跨域工作视图 | `/workbench`，不进入公开导航 | 不是公开内容域、不是公开页面家族、不是第二个后台 |

三层按**可见性和职责**划分，不按内容类型划分。公开站仍然只有 Window 和 Desk 两个页面家族；Workbench 只服务于作者与 agent 的工作流。

## 3. Workbench 需求（R13）

1. **工作项聚合**：在同一个私有视图里看到任务、每周计划、项目进度、Editorial 草稿、审阅队列、Plan 快照状态和 Ops 审批/审计状态；不要求在多个后台之间跳转。
2. **个人任务规划**：记录任务的状态、优先级和下一步，不把任务当成文章类型。
3. **每周计划**：维护周内节奏、待办和下周衔接，不与 Plan 的经济/人生规划混为一谈。
4. **项目进度**：记录项目阶段、进度和下一节点；项目进展不等于公开成果。
5. **审阅与批准**：展示 raw / draft / published 的 diff，支持 L0/L1 自动、L2 人工批准、L3 默认禁止的既定治理。
6. **公开成果投影**：把已批准的内容、规划快照或公开摘要投影到指定公开路由；投影是显式动作，不是自动同步。
7. **边界清晰**：Workbench 不复制 Editorial / Plan / Ops 的 source of truth；每个工作项都指向来源记录，而不是另建一份公开内容库。任务/周计划/项目是 Workbench 私有执行数据，不是第六个公开内容域。
8. **Agent 原生**：人类在 Workbench 能做的每个动作，都有等价的类型化接口；人类 UI 只是同一组 API 的薄客户端。
9. **私有默认**：新建工作项、任务、周计划和项目默认私有、不可索引、不进入公开导航、站点地图和 `llms.txt`；公开必须由明确动作触发。
10. **避风港体验**：低噪声、可恢复、清晰下一步；安全感来自隐私与秩序，不来自暖色装饰或治愈文案。
11. **不伪造内容**：空状态展示结构而不是假文章、假金额、假任务、假项目；原型只使用结构占位和合成 fixture，遵守 R11 的“前期不随意填充文字”。

## 4. 私有默认

以下规则是 D6 的硬边界：

- `/workbench` 必须鉴权；未登录请求不返回任何工作项内容。
- Workbench 所有路由默认 `noindex`，且不进入 `sitemap.xml`、`llms.txt`、公开搜索和公开导航。
- 新建对象默认 `visibility: private`；不存在“默认公开、需要手动隐藏”的路径。任务、周计划和项目进度同样默认私有，不因为“看起来无害”而默认公开。
- 公开投影必须同时满足：来源状态已批准、字段命中白名单、操作者有投影权限、动作被 Ops 记录。
- 日志、错误页、分析事件和截图不得包含私有标题、金额、令牌、审批意见或原文片段。
- agent 凭据按最小权限发放；“读取私有工作项”和“触发公开投影”是不同权限，不得默认合并。
- 删除、撤回、取消投影都必须是可审计动作；撤回后公开路由返回 404/410 或等价状态，不留下可索引缓存。

## 5. 公开成果投影

**投影（projection）不是同步（sync）。** 投影是单向、可撤销的公开动作。对从 Editorial / Plan / Ops 投影的成果，来源域仍是唯一 source of truth；任务/周计划/项目以 Workbench 私有执行为准，但公开时只投影派生摘要。

| 规则 | 说明 |
|---|---|
| 单向 | Workbench → 公开路由；公开页面的修改不回写 Workbench 工作状态 |
| 版本绑定 | 每次投影记录来源 revision（文章 commit / 快照版本）；来源更新不会静默改变已投影内容 |
| 字段白名单 | 只投影 `field_allowlist` 中的字段；未列出的字段保持私有 |
| 显式批准 | 需要人工批准的内容不得由 agent 自行批准；自动投影只适用于预先批准的内容类型和字段 |
| 可撤回 | 支持 unpublish/withdraw；撤回动作进入 Ops 审计 |
| 幂等 | 同一来源 revision + 同一目标路由的重复投影不产生重复公开记录 |
| 可预览 | 投影前可生成与公开页面一致的预览；预览本身仍为私有、`noindex` |
| 不做反向同步 | 公开页面的评论、阅读计数或运营修改不改变 Workbench 的审阅状态 |
| 不投影原始执行数据 | 原始任务列表、周计划明细和项目内部进度不直接公开；只允许经批准的公开摘要/里程碑投影 |

默认投影目标：

- **Desk**：文章、页面、规划快照、经批准的公开摘要等公开成果的主要目标。
- **Window**：只接受明确批准且定义过 Window 呈现契约的公开资产/文案；不默认把 Workbench 状态投影到首页。
- **Workbench 私有执行数据**：只能生成经批准的公开摘要/里程碑投影；不直接投影任务列表或项目内部进度。

## 6. 与 Editorial / Plan / Ops 的边界

| 域 | Workbench 能做什么 | Workbench 不能做什么 | Source of truth | 公开投影 |
|---|---|---|---|---|
| **Editorial 文章域** | 展示草稿、diff、审阅队列和发布状态；触发允许的批准/发布动作；跳转到写作前端或来源文件 | 不在 Workbench 里新建第二套文章库；不替代 Obsidian/Notion；不绕过 raw 不可变和 diff 审阅 | Git 中的 MDX/内容契约 + raw 存档 | 投影为 Desk 文章/页面 |
| **Plan 规划域** | 展示 Ledger Snapshot 的版本、字段可见性矩阵和投影状态；发起投影或撤回 | 不保存原始财务数据；不计算账本；不把支付宝导出或私人明细复制进 Workbench | 独立经济规划项目产出的版本化快照 | 投影为 Desk `/plan/*` 的公开字段 |
| **Ops 运营域** | 读取审批、审计和任务状态；在权限内触发受控动作 | 不铸造令牌、不改权限、不改审计记录；不把 Workbench 当成管理后台 | Ops 的审批/审计/配置存储 | 不公开投影；审计信息不作为公开成果 |
| **Workbench 私有执行数据（任务 / 周计划 / 项目）** | 创建、更新、完成、排期、记录下一步与项目阶段 | 不作为 Editorial 文章类型；不写入 Plan 的公开账本；不自动公开任务列表或项目内部进度 | Workbench 私有执行存储 | 仅投影经批准的公开摘要/里程碑，不投影原始任务列表 |
| **Engagement / Distribution** | 本轮仅可作为只读状态参考 | 不进入 Workbench 首版写路径；不成为新的 source of truth | 各自域 | 不在本轮定义 |

边界判定：

- Workbench 是**跨域工作视图 + 受控动作面 + 私有执行数据**，不是第六个公开内容域，也不是 Timeline 那样的公开读模型。
- 任何“工作项”都必须能指向来源记录；Workbench 自己的任务/周计划/项目是私有执行记录，可指向只读的 Editorial/Plan 引用，但不得成为公开内容的唯一副本。
- 任务/周计划/项目是私有执行数据，不是新的文章类型，也不自动等同于经济/人生规划；经济规划仍由独立项目产生 Ledger Snapshot。
- 冲突时以来源域为准；Workbench 的私有注释不覆盖 Editorial 正文、Plan 快照字段或 Ops 审计事实。
- 公开投影主要从 Editorial 和 Plan 产生；Workbench 私有执行数据只能生成经批准的公开摘要/里程碑投影，不直接投影原始任务列表。Ops 不产生公开投影。

## 7. 结构性字段草案（非旧博客字段）

以下字段只用于讨论结构，**不是最终 schema，也不是从旧博客数据库搬来的字段**。字段名可以替换，但语义边界应保留。

| 记录 | 草案字段 | 含义 / 边界 |
|---|---|---|
| WorkItem | `work_item_id` | Workbench 内部稳定 ID，不用于公开路由 |
| WorkItem | `object_kind` | `weekly_plan` / `task` / `project` / `draft` / `review` / `projection` / `status` 等；仅作工作分类 |
| WorkItem | `source_domain` | `workbench_private` / `editorial` / `plan` / `ops`；`workbench_private` 只用于私有执行记录，不能作为公开内容 source of truth |
| WorkItem | `source_ref` | 指向来源记录的 ID、路径或 commit；`workbench_private` 指向私有执行记录，不复制正文/金额 |
| WorkItem | `source_revision` | 来源版本（commit、快照版本或审计序号） |
| WorkItem | `status` | `private` / `in_review` / `approved` / `projected` / `withdrawn` / `archived` 的草案状态集 |
| WorkItem | `visibility` | 默认 `private`；只有公开投影后才产生公开可见的派生记录 |
| WorkItem | `owner` | `author` / `agent` / `system`；用于权限与审计归属 |
| WorkItem | `projection_target` | `desk` / `window` / `none`；默认 `none` |
| WorkItem | `projection_ref` | 指向投影记录；没有投影时为空 |
| WorkItem | `audit_ref` | 指向 Ops 审计事件；Workbench 不自行保存不可变审计账本 |
| WorkItem | `private_note` | 私有批注；不得被自动投影 |
| WorkItem | `created_at` / `updated_at` | 工作项时间；公开页面时间以来源域为准 |
| Projection | `projection_id` | 投影记录 ID |
| Projection | `projection_kind` | `article` / `plan_snapshot` / `work_summary` 等；`work_summary` 只能来自经批准的公开摘要 |
| Projection | `target` + `public_route` | 目标层与公开路由 |
| Projection | `field_allowlist` | 本次投影允许公开的字段清单 |
| Projection | `source_revision` | 被投影的不可变来源版本 |
| Projection | `approved_by` / `approved_at` | 批准人与时间；自动投影需记录策略来源 |
| Projection | `status` / `withdrawn_at` | `active` / `withdrawn`；撤回后可追溯 |
| Projection | `audit_ref` | 对应 Ops 审计事件 |

实现前必须由 D6 把上述草案收敛为正式契约；在此之前不得把字段名写死到生产代码或 public API。`workbench_private` 记录只能通过派生的、经批准的 `work_summary` 进入公开投影，原始任务/周计划/项目记录永远不直接公开。

## 8. 权限与 agent 对等

- **同一能力，同一接口**：审阅、批准、投影、撤回都通过类型化 API 暴露；Workbench UI 不拥有 agent 没有的隐藏能力。
- **权限分离**：读取私有内容、修改审阅状态、触发公开投影、管理令牌分别授权。
- **幂等与 dry-run**：投影、撤回和批量审阅提供幂等键与 dry-run；失败可重试且不产生重复公开记录。
- **审计**：所有改变状态的动作写入 Ops；Workbench 只展示和触发，不替代审计账本。
- **人类批准点**：L2 表达修改、涉及财务字段的投影、首次公开新内容类型必须有人工批准；agent 不得自批。
- **失败安全**：鉴权失败、来源版本缺失、字段不在白名单时默认拒绝，不“尽量投影”。

## 9. D6 设计门（Workbench）

D6 是新增设计门，不包含在 D0–D5 的首轮闭环内。D6 通过前不进入 Workbench 的生产实现。

| 检查 | 通过条件 | 需要的证据 |
|---|---|---|
| **D6.0 四视图** | 本周 / 任务 / 项目 / 审阅四视图可用；低噪声、清晰下一步、可恢复 | 四视图截图、键盘路径、结构 fixture |
| **D6.1 私有入口** | `/workbench` 需鉴权；未登录无内容；不进入公开导航、sitemap、llms.txt；`noindex` | 路由图、未登录截图、爬虫视图 |
| **D6.2 默认私有** | 新建工作项、任务、周计划、项目默认 private；不存在隐式公开；日志/错误/分析无私有数据 | 合成 fixture、负向测试清单 |
| **D6.3 公开投影** | 字段白名单、来源版本绑定、批准人、幂等、撤回/重投影均可用；`work_summary` 不泄漏原始任务 | projection manifest、撤回演练、审计样例 |
| **D6.4 域边界** | Editorial/Plan/Ops 各自保持 source of truth；任务/周计划/项目为私有执行数据；Workbench 无第二内容库、无原始财务数据、无审计写权限 | 边界图、API 契约草案、冲突演练 |
| **D6.5 Agent 对等** | 人类与 agent 的能力矩阵一致；权限分离；dry-run 与审计可用 | 能力矩阵、MCP/CLI/REST 映射、审计记录 |
| **D6.6 空状态与真实性** | 无假文章、假金额、假任务、假项目；空状态只展示结构说明；遵守 R11 | 空状态截图、fixture 检查 |
| **D6.7 可用性底线** | 键盘可达、焦点可见、状态不只靠颜色；私有页不纳入公开 CWV 预算但需可用 | 键盘/焦点检查、响应式截图 |

D6 的产出是**证据与契约**，不是生产代码。任何一项未通过，D6 保持 pending；不得用“已设计”替代“已验证”。

## 10. StyleKit 参考原则

- **参考 URL**：https://www.stylekit.top/zh
- **核验日期**：2026-10-26（WebFetch 首页；本地曾有 2026-10-23 的 StyleKit 参考截图，现已移到仓库外 `D:\openblog\_archive\design-refs-20261027\`；决策前需重新核对线上页面）。增补原文 `source/requirements-addendum-20261026.md` §3 再次确认：只借鉴系统层方法，不复制模板、提示词、代码或未核验 token。
- **核验到的事实**：页面自称提供 149+ 种风格、60+ 种动画、42+ 个模板；可按 SaaS、Dashboard、作品集、博客内容等场景筛选；博客相关条目包含“编辑杂志风 Editorial”，其描述为衬线标题 + 无衬线正文 + 留白/网格；落地页只给方向性描述，未公开具体字号、行高、间距和色板 token，细节需进入风格详情页或提示词库。
- **不把营销数字当设计证据**：149+/60+/42+ 只说明目录规模，不证明质量、性能、可访问性或授权条件。

### 借鉴（只借系统层）

1. 字号阶梯、间距节奏、配色角色和组件状态的组织方式。
2. 博客/编辑类版式的阅读宽度、标题层级和留白关系；必须回到真实页面测量。
3. “先定系统，再选风格”的方法：避免把单个模板当成整站设计。
4. 作为备选风格目录，用来检验本站是否落入单一模板套路。

### 不采用（明确排除）

1. **不直接复用模板、提示词或代码**：当前未核验其授权与复用条款；如需复用，先单独核验许可。
2. **不采用衬线标题 + 暖纸白底的编辑模板作为默认方向**：这正是用户已否决的“模板感/暖色衬线”风险，见 `_draft/02-visual-ia.md` §4.8 的“反 AI 味”清单。
3. **不采用装饰性渐变、光晕、虹彩或炫技动效**：窗之外仍禁止渐变背景和渐变字。
4. **不把 StyleKit 的示例数值直接当作本站 token**：落地页没有公开完整数值；任何字号/间距/色值必须来自真实页面测量或本站样张验证。
5. **不把 StyleKit 变成依赖或 source of truth**：它只是参考站，不进入构建链、组件库或内容契约。

应用范围：D2（Desk 版式）、D3（资产与主题参考）、D6（Workbench 工具化视觉）可以引用；引用时必须同时写明“借鉴什么、不采用什么、核验日期”。具体拆解以参考站原始 URL、核验日期和后续《参考站拆解》为准；本地截图只作对照，不进入仓库。

## 11. 待决问题

1. Workbench 首版范围：增补要求已包含本周/任务/项目/审阅四视图；Plan/Ops 首版是否只读仍需确认，避免首版变成大而全后台。
2. 任务/项目 schema：任务状态、周计划节奏、项目阶段/下一节点的字段与状态机尚未定义；推荐先用结构 fixture 验证。
3. 鉴权与私有存储：放在独立私有库、私有 Git，还是现有 Ops 的私有 schema？推荐独立私有存储，公开仓库不出现私有工作项。
